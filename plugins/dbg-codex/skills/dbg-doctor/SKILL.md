# Dbg doctor

Dbg 的安装、目录发现、更新和修复已经在脚本中实现。不要让模型重新规划并手工复制插件，也不要写入 CC Switch 或其他客户端的 MCP 配置。

用户要求执行 doctor 时，运行本插件目录下的一条命令：

```text
node <插件根目录>/scripts/launch.cjs doctor
```

脚本会更改已发现工具的扩展和 Dbg 自己的运行时；首次安装与后续运行使用相同流程。它会备份受管文件并保护其他插件。用户给出某个特定工具时，可传 `--tool x64dbg|ghidra|windbg|ida-mcp|ida-export`。

需要机器可读结果时传 `--json`。返回码为 0 表示本轮部署检查完成，1 表示仍有失败项；未发现工具属于跳过，不表示该工具已安装。区分文件部署、MCP 握手和调试器内的实时连接，不把缺失工具的状态服务当成有效调试能力。

显式路径可通过 Dbg 数据目录的 `config.json` 中 `paths` 对象提供，例如 `{"paths":{"ida":["D:/Tools/IDA 9.0"]}}`。只在用户确实指定路径或自动发现不足时使用，不要求所有用户预先配置。

工具启动及首次启用可能需要用户在软件内完成；报告脚本返回的具体状态。不要执行删除项目数据库、退出用户调试会话或修改软件许可证等无关操作。
